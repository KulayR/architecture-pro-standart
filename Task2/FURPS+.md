| Код | Требования                                                                                                                                                                  | Комментарий                                                                                                    |
|-----|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------|
| F   | Функциональные (Functionality)                                                                                                                                              |                                                                                                                |
| F1  | **Подача заявок онлайн:** Клиент должен иметь возможность оформить заявку на депозит и кредит через Сайт (для новых) и Интернет-банк (для действующих).                     | Базовое требование MVP.                                                                                        |
| F2  | **Управление продуктовым каталогом:** Система должна хранить и предоставлять актуальные ставки по депозитам и кредитам централизованно (отказ от Excel-файлов при расчете). | Сейчас ставки считаются вручную. Логику нужно перенести в АБС или новый микросервис «Продуктовый каталог».     |
| F3  | **Персонализация:** В интернет-банке клиенту должны отображаться персонализированные ставки по депозитам и предодобренные предложения по кредитам.                          | Требует интеграции с CRM/Скорингом в режиме чтения профиля.                                                    |
| F4  | **Подтверждение операций:** Все значимые действия (подача заявки, открытие счета) должны подтверждаться через СМС-код.                                                      | Требует интеграции с СМС-шлюзом. В ядре функционал есть, но требует доработки силами банка.                    |
| F5  | **Сквозной процесс заявки:** Если клиент начал заявку на Сайте/в ИБ, сотрудник в отделении должен видеть эту заявку в АБС и продолжать работу с ней, а не создавать новую.  | Критично для кредитного процесса, где заявка может быть предварительно одобрена онлайн.                        |
| F6  | **Онлайн-скоринг:** Для новых клиентов на сайте — экспресс-оценка через БКИ. Для действующих — пересчет лимитов при подаче заявки (если ситуация изменилась).               | Требует интеграции Сайта с сервисом Скоринга (минуя суточный батч АБС).                                        |
| F7  | **Информирование:** Отправка СМС-уведомлений клиенту при изменении статуса заявки (Одобрено/Отказ/Требует визита).                                                          |                                                                                                                |
| U   | Удобство использования (Usability)                                                                                                                                          |                                                                                                                |
| U1  | **Единая дизайн-система:** Интерфейсы новых модулей (депозиты, кредиты) должны соответствовать принятому брендбуку и UI-киту компании.                                      | Пользователь не должен чувствовать переход между старым монолитом и новыми микросервисами.                     |
| U2  | **Отзывчивость UI:** Отклик интерфейса на действия пользователя не должен превышать 200–500 мс (субъективное «мгновенно»).                                                  | Текущая проблема с загрузкой справочников (>1 сек) должна быть решена (кеширование на фронте/BFF).             |
| U3  | **Минимизация ввода:** Для действующих клиентов поля заявки должны предзаполняться данными из профиля банка.                                                                |                                                                                                                |
| R   | Надёжность (Reliability)                                                                                                                                                    |                                                                                                                |
| R1  | **Доступность 24/7 (99.9%):** Сервисы подачи заявок должны работать круглосуточно, даже во время ночных закрытий дня в АБС.                                                 | Требует архитектурной развязки: ИБ не должен «умирать», если АБС занята регламентными работами.                |
| R2  | **Отказоустойчивость:** Система должна поддерживать переключение на резервный ЦОД в случае аварии основного.                                                                | Данные должны реплицироваться между ЦОД.                                                                       |
| R3  | **Изоляция сбоев:** Сбой в АБС или Кредитном конвейере не должен приводить к падению Сайта или Интернет-банка.                                                              | Фронт должен уметь принимать заявку в буфер (очередь), даже если бэкенд временно недоступен.                   |
| R4  | **Сохранность данных:** Ни одна поданная заявка не должна быть потеряна при сбоях интеграции.                                                                               | Гарантированная доставка сообщений (использование очередей, например, Kafka).                                  |
| P   | Производительность (Performance)                                                                                                                                            |                                                                                                                |
| P1  | **Защита АБС от нагрузки:** Онлайн-заявки не должны создавать прямую нагрузку на БД АБС.                                                                                    | АБС уже перегружена. Чтение данных должно идти из кешей/реплик, запись — через асинхронную очередь.            |
| P2  | **Масштабируемость:** Новые сервисы (депозиты, кредитный фронт) должны поддерживать горизонтальное масштабирование.                                                         | АБС масштабируется только вертикально, поэтому выносим логику из неё в микросервисы.                           |
| P3  | **Скорость принятия решений:** Решение по кредиту для нового клиента (через сайт) должно выдаваться в режиме реального времени (секунды/минуты), а не через сутки.          | Уход от Batch-процесса обмена с Кредитным конвейером.                                                          |
| S   | Поддерживаемость (Supportability)                                                                                                                                           |                                                                                                                |
| S1  | **Микросервисная архитектура:** Новый функционал (открытие депозитов/кредитов) реализовывать в виде отдельных микросервисов, а не дорабатывать монолит Интернет-банка.      | Позволит обновлять эти продукты независимо от подрядчика ядра ИБ.                                              |
| S2  | **Технологический стек:** Использование Java Spring Boot (есть экспертиза в команде АБС/КЦ), БД PostgreSQL/Oracle.                                                          | Использование Python только для ML-моделей (скоринг), но бизнес-логику лучше держать на Java (стандарт банка). |
| S3  | **Асинхронность (Kafka):** Использование Apache Kafka в качестве брокера сообщений для интеграции микросервисов и легаси-систем.                                            | Требование на перспективу, но критично для развязки скоростей быстрого фронта и медленного бэка.               |
| S4  | **Документирование API:** Наличие актуальной Swagger/OpenAPI документации для всех новых сервисов.                                                                          |                                                                                                                |
| +R  | + Ограничения (Restrictions)                                                                                                                                                |                                                                                                                |
| +R1 | **Безопасность данных:** Обязательное шифрование трафика (TLS/SSL) между клиентом и сервером, а также внутри контура банка при передаче чувствительных данных.              | Требование безопасности, особенно для паспортных данных с сайта.                                               |
| +R2 | **Совместимость с Legacy:** Текущий Интернет-банк (ASP.NET) не умеет работать с Kafka напрямую.                                                                             | Потребуется разработка адаптера (Connector) или использование REST-фасада перед Kafka для старого монолита.    |
| +R3 | **Кадровые ресурсы:** Приоритет технологиям, знакомым текущим командам (Java, PL/SQL, React, .NET). Избегать экзотики, если нет экспертизы.                                 |                                                                                                                |
| +R4 | **Защита системы скоринга:** Не нагружать систему скоринга лишними «пред-расчетами» в часы пик.                                                                             | Расчет предодобренных предложений должен проводиться в периоды низкой нагрузки (ночью) и кешироваться.         |
